# BLE RAW Reader · 智能开关数据读取器

一个极简的 Android BLE 广播数据读取工具：打开即扫描指定设备，实时显示广播包的十六进制原始字节，一键复制。

| | |
|---|---|
| 语言 | Kotlin（原生 View，无 AndroidX） |
| 依赖 | 零第三方库，仅 Android 系统 API + Kotlin 标准库 |
| 包体 | debug APK 约 840 KB |
| 系统要求 | Android 8.0（API 26）及以上 |

---

## 它解决什么问题

通用的 BLE 调试 App（例如 nRF Connect）是功能完备的工具箱：扫描周边所有设备、连接、浏览 GATT 服务与特征、读写描述符。代价是「看一眼某台设备的广播原始数据」这件事被埋在好几层入口后面——打开 App、等扫描列表刷出来、从十几台设备里找到目标、点进去、切到 RAW 视图。偶尔看一次，这套动作每次都要重来。

而需求本身只有三步：**看哪台设备 → 它的广播原始数据是什么 → 复制走**。

本项目只做这三步：

- 没有设备列表，不需要从一堆信号里挑设备。目标设备的 MAC 保存在配置里，启动只认它一个，其它设备的数据连界面都进不去。
- 不建立连接，不读 GATT，纯被动监听广播，对目标设备无任何影响。
- 主界面只有「信号强度 + 原始数据 + 复制按钮」，没有多余入口。

适合的场景：盯某台设备广播内容的变化、把一段十六进制广播包拷到电脑上解析、快速确认设备是否在正常广播。

## 功能特性

| # | 功能 | 说明 |
|---|---|---|
| 1 | 打开即扫描 | 启动自动开始 BLE 扫描，不需要点任何按钮 |
| 2 | 只显示指定设备 | 按 MAC 精确匹配，只渲染这一台设备的数据，周围其它设备一律不显示 |
| 3 | 实时 RAW + RSSI | 广播包更新即刻刷新十六进制数据，同时显示信号强度（dBm） |
| 4 | 一键复制 | 顶部按钮把当前原始数据复制到剪贴板，支持三种格式 |
| 5 | 变化才记录 | 数据与上一条不同时才落库，相同数据不重复写 |
| 6 | 记录管理 | 倒序展示、分页加载、点行复制、一键清空 |
| 7 | 高级设置 | 修改目标 MAC / 恢复默认 / 切换复制格式 / 查看与清空记录 |

### 设计一：只显示指定设备

扫描回调里先按 MAC 过滤，不匹配的设备直接丢弃。这样界面永远只有一台设备的数据，不会因为旁边有十几个 BLE 设备而反复跳变、看错对象。

目标 MAC 存在本地 `SharedPreferences`，出厂是占位值（见「界面说明」），**必须改成你自己的设备地址**才能收到数据。

### 设计二：变化才记录

广播是持续重复发送的，同一段内容一秒可能来好几包。如果按包记录，几分钟就能把存储写满，列表里也全是重复行。

`RecordStore` 在插入前与「最新一条」比较：内容相同就跳过，只有真正变化时才写入一条 `(时间, 数据)`。因此历史记录等价于一份**变更时间线**——每一行都代表「这一刻数据变了」，比原始包流有用得多。

上限 1000 条，超出后自动删除最旧的记录，不会无限增长。

### 复制格式

| 格式 | 输出示例 | 说明 |
|---|---|---|
| 连续无空格 | `0201060B09...` | **默认**，适合整段粘贴到其它工具解析 |
| 空格分隔 | `02 01 06 0B 09 ...` | 适合人眼逐字节核对 |
| `0x` 数组 | `0x02, 0x01, 0x06, ...` | 适合直接贴进 C / Java / Kotlin 代码 |

界面上的数据是分行分块显示的（便于阅读），**复制出去的是按选定格式拼接好的一整串**。

## 界面说明

主界面从上到下只有这些元素：

```
智能开关                     正在扫描智能开关
──────────────────────────────────────────
未命名智能开关
信号 -47 dBm
──────────────────────────────────────────
智能开关数据
02 01 06 0A FF 12 34 05 0A 0B 0C 0D 0E
0F 03 03 0D 18 07 16 0F 18 0A 18
──────────────────────────────────────────
[           复制智能开关编号           ]
          由 禁止熬夜 开发
```

示意图中的数据为示例字节，实际显示取决于目标设备的广播内容。

界面文案采用简明的产品化措辞：应用名、区块标题、按钮统一使用「智能开关…」的说法；技术参数与高级操作集中在「高级设置」页，主界面保持单一职责。底部一行是固定的开发者署名文案。

> **首次使用必须先设置 MAC 地址**
>
> 出厂默认 MAC 是占位值 `00:00:00:00:00:00`，用它扫不到任何设备，界面会一直停在「等待数据」。这不是应用坏了。
>
> 设置方式：**在 3 秒内连续点击左上角标题 10 次** → 进入「高级设置」→ 填入目标设备 MAC → 保存。返回主界面后会自动用新地址重新扫描。
>
> 支持的写法：`AA:BB:CC:DD:EE:FF`、`AA-BB-CC-DD-EE-FF`、`AABBCCDDEEFF`。

高级设置里的项目：

| 项目 | 作用 |
|---|---|
| 当前锁定 MAC 地址 | 修改目标设备地址，保存后立即生效 |
| 恢复默认 | 回到出厂占位值 |
| 复制格式 | 空格分隔 / 连续无空格 / 0x 数组，三选一 |
| 查看记录（N 条） | 进入历史记录页 |
| 清空记录 | 二次确认后清空 |

历史记录页：倒序排列，最新在最上面；每页 200 条，底部「加载更多」；**点击某一行 = 复制该行数据**；右上角「清空」带二次确认。

## 构建方式

环境要求：

| 项目 | 版本 |
|---|---|
| JDK | 17 |
| Kotlin | 1.9.24 |
| Android Gradle Plugin | 8.1.4 |
| Gradle | 8.x |
| compileSdk / targetSdk | 33 |
| minSdk | 26（Android 8.0） |
| applicationId | `com.ble.rawreader` |

步骤：

1. 在工程根目录创建 `local.properties`，写入本机 SDK 路径：

   ```properties
   sdk.dir=/path/to/Android/Sdk
   ```

   该文件不入库，已在 `.gitignore` 中排除。

2. 构建：

   ```bash
   gradle :app:assembleDebug
   ```

3. 产物：`app/build/outputs/apk/debug/app-debug.apk`

几点说明：

- 项目关闭了 AndroidX（`android.useAndroidX=false`），也关闭了 Jetifier，依赖解析几乎为零，构建很快。
- `dependencies` 里只有 `kotlin-stdlib`，没有任何第三方库。
- 如果仓库路径包含非 ASCII 字符（例如中文目录名），Gradle 默认会因路径检查直接报错，需要在 `gradle.properties` 中保留 `android.overridePathCheck=true`。
- 构建脚本里配置了国内镜像仓库；如果在境外网络下构建缓慢，可自行调整 `build.gradle` / `settings.gradle` 中 `repositories` 的顺序。

## 权限说明

| 权限 | 适用版本 | 为什么需要 |
|---|---|---|
| `BLUETOOTH_SCAN` | Android 12+（API 31+） | 新版系统把蓝牙扫描拆成独立的运行时权限，不授予则收不到任何广播 |
| `BLUETOOTH` / `BLUETOOTH_ADMIN` | Android 11 及以下（`maxSdkVersion=30`） | 旧版系统的传统蓝牙权限，扫描 BLE 必需 |
| `ACCESS_FINE_LOCATION` / `ACCESS_COARSE_LOCATION` | 全版本声明 | Android 6~11 把 BLE 扫描视为可推断位置的行为，没有位置权限扫不到结果；部分厂商 ROM 在 Android 12+ 仍沿用这一限制，故一并声明 |
| `android.hardware.bluetooth_le`（`uses-feature`，required） | 全部 | 声明依赖 BLE 硬件，避免被安装到没有 BLE 的设备上 |

权限被拒时界面只提示「需要授权后才能使用」，不会崩溃；重新授予后即可正常扫描。

**应用不申请 `INTERNET` 权限，不联网、不上报、不统计、不做云端同步。** 目标 MAC 与历史记录只存在本机。

## 技术说明

### 零第三方依赖

| 能力 | 实现方式 |
|---|---|
| BLE 扫描 | `android.bluetooth.le.BluetoothLeScanner` + `ScanCallback` |
| 界面 | 原生 `View` / `Activity` / XML 布局（无 AndroidX、无 Material、无 Compose） |
| 本地存储 | 系统自带 SQLite（`android.database.sqlite`） |
| 配置 | `SharedPreferences` |
| 语言 | Kotlin 标准库 |

没有第三方库，也没有 AndroidX。因此 APK 只有约 840 KB，方法数极少，冷启动快，也不会因上游库版本变动而腐化。`android.database.sqlite` 属于 Android 框架 API，不计入第三方依赖。

扫描参数为 `SCAN_MODE_LOW_LATENCY` + `CALLBACK_TYPE_ALL_MATCHES`，不设置 `reportDelay`，每次回调立即刷新界面。

### 「RAW」在这里指什么

本项目显示的 RAW 值 = **广播包的原始字节**，即 `ScanResult.getScanRecord().getBytes()`，包含 Advertising Data 与 Scan Response Data 两部分（设备若发送了 scan response）。

它与 nRF Connect 等工具里的 RAW / 原始数据视图等价，**不是** GATT 特征值（characteristic value），也**不是**解析后的字段。取到的就是字节流本身，长度、AD Type、payload 的解析交给使用者在自己的工具里做。

- 不调用 `connectGatt()`，不与设备建立任何连接；
- 不读写 GATT 服务与特征；
- 仅被动接收扫描回调。

### 记录存储

- 表结构极简：`(id, timestamp, data)`，`data` 存十六进制字符串；
- 插入前与最新一条比对，相同则丢弃；
- 总数超过 1000 时删除最旧的记录；
- 查询按 `timestamp DESC` 分页，每页 200 条；
- 清空操作为整表删除，带二次确认。

## 已知限制

- **只能看广播，看不到 GATT。** 需要连接后才能读取的服务、特征、电量、传感器值，本工具一概拿不到——这是被动监听的固有边界。
- **广播包格式因厂商而异。** 同样是「电量」，有的厂商放在 Manufacturer Specific Data 里，有的塞进自定义 AD Type，字节序也各不相同。本工具只提供原始字节，不负责解读。
- **回调频率受系统调度影响。** 同一台设备在不同手机、不同系统版本上看到的变化节奏可能不一样。
- **高频广播可能被系统合并或节流。** 部分 ROM 对密集广播有去重或限流行为。
- **写死 MAC 会失效于随机地址设备。** 有些设备会周期性更换广播地址，这种情况需要用其它方式匹配。
- **仅前台运行。** 没有前台服务与后台常驻逻辑，退到后台后扫描停止。
- **未处理多语言与横屏。** 界面固定竖屏，文案为中文。
